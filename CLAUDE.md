# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

FTLM is a **brick-breaker / Breakout-style game** (jeu de casse-brique) built with the **Godot 4.6.3 (.NET/Mono)** engine, written in **C#**. It is a playable game: a paddle moved with the arrow keys, a ball, multiple **levels** of destructible (multi-hit) bricks, falling **bonus/malus capsules**, **multi-ball**, **score/lives/best-score**, **sound effects + particles**, and a **menu / pause** flow. The Godot engine is driven through the **`godot-mcp` MCP server** (see below). See [AGENTS.md](AGENTS.md) for additional notes maintained alongside this file.

## Toolchain & Commands

The `godot` executable is **not on PATH**. Use the full path:
`C:\DEV\Godot\Godot_v4.6.3-stable_mono_win64_console.exe` (the `_console` variant for CLI/headless work).

- **Build C#:** `dotnet build` (also wired as the VS Code `build` task, run automatically before debug launches).
- **Run the game:** `& "C:\DEV\Godot\Godot_v4.6.3-stable_mono_win64_console.exe" --path .`
- **Run the auto-test:** append `-- --test` to the run command. It self-drives a full play-through and prints `[TEST] …` to the console, then quits. `godot-mcp run_project` cannot pass CLI args, so use the console exe directly for this. (A non-fatal "resources still in use at exit" warning is expected — the test force-quits while particles/timers are alive.)
- **Open the editor:** append `--editor` to the run command.
- **Network two-instance test:** launch one host (`-- --nethost`) and one client (`-- --netjoin`, joins `127.0.0.1`); both auto-drive a host+client session and print `[NET] …` lines (briques/balles counts, slot, ball Y), then quit. Run the host in the background first, then the client; the client retries the connection until the host is up. Used to validate the réseau sync end-to-end without clicking through the lobby.
- **Re-import assets** (after adding files like the `Audio/` WAVs): `--headless --import`.
- **Debug (VS Code):** the `Launch` / `Launch Editor` configs in [.vscode/launch.json](.vscode/launch.json) build first, then attach the `coreclr` debugger. They resolve the Godot binary from the `godot-dotnet-tools.executablePath` setting.

### Driving Godot via MCP
The `godot-mcp` server is configured in [.mcp.json](.mcp.json) (with `GODOT_PATH` set to the console build). Prefer its tools for engine operations — `run_project` (returns debug output/errors), `get_debug_output`, scene/node editing, `launch_editor`. This is the most reliable way to run the project and read runtime errors. Requires a Claude Code reload after `.mcp.json` changes.

## Architecture

- **Entry point:** `run/main_scene = res://MainMenu.tscn` ([project.godot](project.godot)); the "Nouveau" button opens a **player-selection screen** (built in code in [Scripts/MainMenu.cs](Scripts/MainMenu.cs): 2/3/4 joueurs, Humain/IA par emplacement) then loads the gameplay scene **[Jeu.tscn](Jeu.tscn)**. `MainMenu` also boots straight into `Jeu.tscn` when launched with the `--jeu` or `--test` CLI arg (defaulting to the 2-camp Joueur-vs-IA duel). The C# assembly name is also `FTLM`.
- **Multiplayer (2/3/4 joueurs):** the arena is **generated at runtime** from N pivoted "arms" (couloirs) radiating from a central hub at world **`(0,5,0)`**. Each arm is an instance of **[Arm.tscn](Arm.tscn)** (paddle `Bar` + `Area3D` `ZoneMort` + empty `Ville`/`Briques`/`Capsules` containers, in the original player-side local coordinates), rotated about the hub by its angle (2p: 0°/180° = the old vertical duel; 3p: 0/120/240 = Y; 4p: 0/90/180/270 = cross). Boundary walls and the hub connectors are generated in `GameManager.ConstruireMurs`. Per-mode geometry (corridor half-width, brick columns, camera) lives in `GameManager.AppliquerGeometrie`/`PlacerCamera`. The match config is held in the static **[Scripts/PartieConfig.cs](Scripts/PartieConfig.cs)**.
- **Multijoueur réseau (hôte autoritaire) :** the **[Scripts/NetworkSession.cs](Scripts/NetworkSession.cs)** autoload (registered in [project.godot](project.godot) `[autoload]`) owns the `ENetMultiplayerPeer` (host `CreateServer`, client `CreateClient`, port `42424`), the lobby (slot→peer assignment, UPnP port mapping on a background thread), and the synchronised start. The menu's **Héberger**/**Rejoindre** buttons drive it. `PartieConfig.Mode` is `Local` or `Reseau`; `TypeControle` adds `HumainDistant`; `PartieConfig.SlotLocal`/`PeerControleurDe` map machines to slots. In `Reseau` mode **only the host simulates** — gameplay logic in `GameManager` is unchanged; the network glue lives in the partial **[Scripts/GameManager.Reseau.cs](Scripts/GameManager.Reseau.cs)**. The host broadcasts ~30 Hz snapshots (bar X + ball/capsule positions, reconciled by network ID) and reliable events (brick despawn/hit, building destruction, level change, HUD ~5 Hz); clients regenerate the arena deterministically (same brick IDs), request an initial state on load, and otherwise only display. `BarScript.ModeControle` (Local/IA/Distant/Spectateur) and the display modes on `BalleScript`/`CapsuleScript` (frozen, no physics, position set from snapshots) implement "client = affichage seul". Clients send their arrows/space input to the host (`HoteRecevoirAxe`/`HoteRecevoirLancer`), which verifies the sender controls that slot. Bricks/balls/capsules carry an `IdReseau`.
- **Gameplay scene** ([Jeu.tscn](Jeu.tscn), root node `Jeu`): now just the shared shell — a background `Fond`, empty `Bras` (holds generated arms) and `Murs` (holds generated walls) containers, a `Camera3D`, a `DirectionalLight3D`, the `PauseMenu`, and a **`HUD`** `CanvasLayer`. Per-player score/lives/bonus info is shown in up to four **corner panels** built in code. Ball `RigidBody3D` containers are created under a runtime `BallesRoot` (kept out of the rotated arms, since a rigidbody must not be a child of a rotated node).
- **Orchestrator** ([Scripts/GameManager.cs](Scripts/GameManager.cs)): attached to the root node; runs with `ProcessMode = Always` (so pause works). Owns the game state machine (`Menu` → `AttenteLancement` → `EnJeu` → `Pause`/`GameOver`/`Victoire`), level data (string-pattern grids), brick generation, ball/capsule spawning, bonus effects, scoring, audio, particles, and best-score persistence (`user://meilleur_score.dat`). It resolves scene nodes via `GetNode` in `_Ready` (typed `[Export]` node refs do **not** resolve reliably when hand-written into `.tscn` for .NET).
- **Reusable instanced scenes:** [Balle.tscn](Balle.tscn) (ball, `RigidBody3D`, group `balle`), [Brique.tscn](Brique.tscn) (brick, `StaticBody3D`, group `briques`), [Capsule.tscn](Capsule.tscn) (bonus, `Area3D`), [Explosion.tscn](Explosion.tscn) (`CpuParticles3D` burst). Each has a matching `Scripts/*Script.cs`.
- **Ball** ([Scripts/BalleScript.cs](Scripts/BalleScript.cs)): the `GameManager` launches it (`Lancer`), keeps a constant speed by re-normalizing `LinearVelocity` each physics frame, and sets the rebound angle off the paddle via `RebondSurBarre`. Per-ball `BodyEntered` is wired by the manager with a closure capturing the ball. Z axis locked, gravity off, frictionless/bouncy material → X/Y plane only.
- **Paddle** ([Scripts/BarScript.cs](Scripts/BarScript.cs)): moves on its **local X** (each paddle is a child of its rotated arm), using the per-player action pair passed to `Configurer` (J1 = `ui_left`/`ui_right` + mouse; J2-J4 = `j2_*`/`j3_*`/`j4_*` registered by `PartieConfig.EnregistrerActions`), clamped within the corridor; `Redimensionner(facteur, duree)` for the size bonus/malus. Ball launch/rebound directions are expressed as global **axes** (`AxeAttaque`/`AxeLateral`) derived from the arm basis, not a `±1` Y sense.
- **Audio:** WAV files in `Audio/` generated procedurally (short tones); loaded into per-sound `AudioStreamPlayer`s in `GameManager._Ready`.
- **Auto-test harness** ([Scripts/GameManager.Test.cs](Scripts/GameManager.Test.cs)): a `partial` of `GameManager`, gated by the `--test` CLI arg (2-camp duel). Injects input via `Input.ParseInputEvent` and logs `[TEST] …` lines, then quits. The same partial also holds a **smoke mode** (`--smoke2`/`--smoke3`/`--smoke4`): all-IA, runs ~600 frames and prints `[SMOKE] …` confirming no ball escapes the generated arena. When piping output, redirect to a file (`> log 2>&1`) — `GetTree().Quit()` can truncate the tail of a pipe. Removable without touching the game.
- **Input:** `lancer_balle` (Space + **left mouse**) **launches/relaunches the ball only**; `tirer_capacite` (Alt/AltGr + **right mouse**) fires the laser / active ability (`GererCapaciteCamp`). Both are defined in [project.godot](project.godot) and remappable in the Options menu (the mouse buttons are fixed bindings re-added by `SettingsManager.AjouterEntreesFixes`). `ui_left`/`ui_right`/`ui_cancel` are engine defaults (arrows + Escape for pause). Per-player movement + action + ability actions `j2_gauche/j2_droite/j2_action/j2_capacite` (A/D/W/S), `j3_*` (J/L/I/K), `j4_*` (Numpad 4/6/5/8) have their defaults in `PartieConfig` (registered at runtime by `PartieConfig.EnregistrerActions`, and surfaced through `SettingsManager` so they are persisted and remappable). The Options ▸ Touches tab builds a **per-player grid** (action × Joueur 1-4) in code in [Scripts/OptionsMenu.cs](Scripts/OptionsMenu.cs) (`ConstruireTouches`); the `.tscn`'s `TouchesBox` is left empty.
- **Physics:** **Jolt Physics**. Walls share the frictionless, fully-bouncy material [Physics_Material/Mur.tres](Physics_Material/Mur.tres).
- **Rendering:** Forward+ renderer, Direct3D 12 driver on Windows.
- **C# targets** ([FTLM.csproj](FTLM.csproj)): `net8.0` on desktop, `net9.0` when `GodotTargetPlatform == android`. Code analysis uses [.vscode/ruleset.xml](.vscode/ruleset.xml), which disables `CA1050` (namespace warning) — Godot scripts are intentionally namespace-less `public partial` classes extending engine node types.

## Conventions

- **Preserve the French node names** inside [Arm.tscn](Arm.tscn) (`Bar`, `ZoneMort`, `Ville`, `Briques`, `Capsules`) and existing comments — `GameManager` resolves them by name per arm via `GetNode`. (Walls are generated as `Mur` nodes under `Murs`; ball containers are created under `BallesRoot`.) Code, identifiers, and comments are in **French** — match that.
- Scripts are `public partial` classes extending a Godot node type, with `_Ready` / `_Process` overrides. Match this style.
- Files are UTF-8 ([.editorconfig](.editorconfig)).
- Prefer editing scenes/resources through the Godot editor (or `godot-mcp`) over hand-editing `.tscn`/`.tres`; small textual edits are fine when the structure is clear.
- The repository is **not** a git repo.
